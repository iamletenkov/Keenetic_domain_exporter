**Keenetic Domain Exporter**

Утилиты для экспорта/импорта FQDN-групп (domain-listN) в конфигурацию маршрутизаторов Keenetic.

Проект содержит два скрипта, которые работают непосредственно с конфигом устройства через `ndmc`/`ndmq` (обычно из Entware):

- **`export.sh`**: экспортирует группы `object-group fqdn domain-listN` из `running-config` в папку `lists` рядом со скриптом.
- **`import.sh`**: читает файлы из папки `lists` и создаёт/обновляет соответствующие `object-group fqdn` в конфиге, а также назначает `dns-proxy route` на выбранный VPN-интерфейс.

**Коротко**
- **Назначение**: удобно переносить/версионировать списки доменов (FQDN) между устройствами или хранить их в git.
- **Требования**: Keenetic + Entware (команды `ndmc`, `ndmq`), POSIX shell (BusyBox ash/awk достаточно).

**Установка / подготовка**
- **Entware**: скрипты ожидают, что `ndmc` доступен в PATH. Для `import.sh` также нужен `ndmq` (скрипт попытается установить его через `opkg`, если он доступен).
- Скопируйте репозиторий или только `export.sh`/`import.sh` на устройство в любую папку и сделайте их исполняемыми:

```
chmod +x export.sh import.sh
```

**Формат папки `lists`**
- Расположена рядом со скриптами: `./lists`.
- Каждый файл — это один список. Имя файла (без `.txt`) используется как `description` при импорте, и/или как имя файла при экспорте (sanitize -> заменяются недопустимые символы на `_`).
- Поддерживаемые строки внутри файлов:
	- Обычная строка `example.org` — добавляется как `include` домен.
	- Строки `include example.org` и `exclude example.org` — явно задают действие (поддерживается `export` в режиме `actions`).
	- Строки, начинающиеся с `!` или `-` — считаются `exclude`.
	- Комментарии: строки, начинающиеся с `#`, игнорируются.

**`export.sh` — использование**
- По умолчанию экспортирует только `include` домены (простой формат: по одному домену на строку).
- Если нужно экспортировать с явными действиями (`include`/`exclude`), используйте переменную окружения `EXPORT_MODE=actions`.

Примеры:

```
sh export.sh
EXPORT_MODE=actions sh export.sh
```

Поведение и важные детали `export.sh`:
- Читает текущий конфиг через `ndmc -c "show running-config"`.
- Экспортирует только группы, имя которых совпадает с `domain-listN`.
- Файлы создаются в `./lists` с расширением `.txt`.

**`import.sh` — использование**
- Синтаксис:

```
sh import.sh [-i IFACE] [-d DIR] [--no-route] [--dry-run] [--no-save]
```

- Параметры:
	- **`-i IFACE`**: использовать указанный VPN-интерфейс без интерактивного выбора.
	- **`-d DIR`**: папка со списками (по умолчанию `./lists`).
	- **`--no-route`**: не назначать `dns-proxy route` для групп.
	- **`--dry-run`**: печатать команды вместо выполнения (для проверки).
	- **`--no-save`**: не выполнять `system configuration save` после изменений.
	- **`MAX_INDEX` (env)**: максимальный индекс при автоматическом выделении `domain-listN` (по умолчанию `199`).

Примеры:

```
sh import.sh --dry-run
sh import.sh -i Wireguard1
sh import.sh -d /path/to/lists --no-save
```

Поведение и важные детали `import.sh`:
- Читает `running-config` через `ndmc` и строит карту `description -> group`.
- Для каждого файла из `lists` пытается найти существующую группу с таким `description`. Если не находит — аллоцирует первый свободный `domain-listN` (0..`MAX_INDEX`).
- Пересоздаёт (удаляет старую и создаёт новую) группу с нужным описанием, затем добавляет `include`/`exclude` записи и назначает `dns-proxy route object-group <group> <iface> auto` (если `--no-route` не задан).
- Для выполнения CLI-команд используется `ndmq -p` (скрипт попытается найти/установить `ndmq` через `opkg`).

**Примеры рабочего процесса**
- Экспорт с устройства в git-репиторий:

```
# на Keenetic
sh export.sh
# затем скопировать ./lists на локальную машину и закоммитить
```

- Импорт (выполнение на Keenetic, проверка перед применением):

```
sh import.sh --dry-run
sh import.sh -i Wireguard1
```

**Отладка и распространённые ошибки**
- Ошибка: `ndmc` не найден — запустите скрипты на Keenetic с Entware или добавьте `ndmc` в PATH.
- Ошибка: `ndmq` не найден — `import.sh` попытается установить его через `opkg`. Убедитесь, что Entware установлен и `opkg` доступен.
- Если `running-config` пуст или `ndmc` не возвращает данные, скрипты завершат работу с сообщением об ошибке.

**Безопасность и особенности**
- Скрипты выполняют изменения конфигурации маршрутизатора. Всегда используйте `--dry-run` для проверки команд перед применением в продакшн.
- `import.sh` по умолчанию выполняет `system configuration save`. Если хотите применить изменения временно — используйте `--no-save`.
